Several agents on one feature

Split a feature into parts that touch different files, and give each part to its own agent. Each works in its own worktree, a second working copy of your project, so they don’t trip over each other.

  1. Commit your work first. Agents start from your last commit, and changes you haven’t committed stay behind.
  2. Start one task per part, each with @shop: 
    @shop add an API for saved carts: GET and PUT /api/carts/{id}
@shop build the saved carts page, calling GET /api/carts/{id}
@shop write tests for saving and loading carts
  3. Watch the rows. Answer the ones that turn red, and leave the rest alone.
  4. When a row shows ✓, look in, then read its branch, its line of changes, from your checkout: 
    cd ~/code/shop
git log --oneline HEAD..irie/add-an-api-for-saved
git diff HEAD...irie/add-an-api-for-saved
  5. Merge each branch, or push it and open a pull request, a change sent for review: 
    git merge irie/add-an-api-for-saved
  6. Once a branch is merged, remove its worktree and branch: see When you’re done.

Agents don’t see each other’s changes until you merge them. For a part that builds on another, merge the first, then start the next.

What works today

  • A worktree and a branch for every @shop task, with your local files copied in.
  • Rows that turn red when an agent needs you, whichever row you’re looking at.

What is planned

  • Sending a working agent a note, such as a change its neighbour made. Planned
  • Telling each agent which others work in the same repo, and on which branches. Planned
  • A review of each branch by another company’s model before it reaches you. Planned

A local model for small jobs, a cloud model for hard ones

Keep the default, Claude Code with Opus 5.5, for hard work, and add a profile for a model on your own computer. A profile is a recipe you name for starting an agent.

[profiles.local]
model = "gpt-oss:20b"
env = { ANTHROPIC_BASE_URL = "http://127.0.0.1:11434", ANTHROPIC_AUTH_TOKEN = "ollama", ANTHROPIC_API_KEY = "" }

Restart Irie’s core so it reads the new profile: see how. Then choose for each task:

@shop +local add comments to cart.go
@shop +local rename the variable tot to total in cart.go
@shop redesign the checkout flow

Give the local model jobs that are easy to check, such as comments, renames and small tests, and look over what it did. Give it enough room first: see Profiles for local models.

What works today

  • A profile per model, picked for each task with +, and completed with Tab.
  • Any local server that speaks Anthropic’s API, such as Ollama, LM Studio or llama-server.

What is planned

  • A check that a local model has room enough before its agent starts, with the fix if it hasn’t. Planned
  • Irie choosing the profile for you, by how hard the task is and how much of your plan is left. Planned
  • Moving a task to another profile when it hits a usage limit. Planned

Scripting Irie with irie ctl spawn --wait

A script, a file of commands run in a row, can start agents and wait for them, with no window open. This one starts a task, then checks every 10 seconds until it’s done or needs you:

#!/bin/sh
set -e
id=$(irie ctl spawn --wait @shop "fix the flaky checkout test")
while :; do
  state=$(irie ctl list | awk -v id="$id" '$1 == id { print $2 }')
  case $state in
    done|idle) echo "$id is done"; break ;;
    needs_you|stalled|failed|exited) echo "$id: $state" >&2; exit 1 ;;
  esac
  sleep 10
done

--wait returns once the agent is working, and fails if it never gets there, so set -e stops the script. Start many tasks from a file, one per line:

while IFS= read -r task; do
  irie ctl spawn @shop "$task"
done < tasks.txt

Pass a long task as a file, and follow one agent’s steps as they happen:

irie ctl spawn --wait --name refactor-cart @shop - < refactor.md
irie ctl watch --session "$id"

What works today

  • irie ctl spawn, list, show and watch, all described in Keys and commands.
  • Starting Irie on the first spawn, with no window open.

What is planned

  • Pausing, freezing and sending notes from scripts, as each arrives. Planned
  • irie ctl preflight and spawn --force for local models. Planned

A quick fix in your own checkout

When a worktree is more than a job needs, add ! to work in the repo’s own folder:

@shop! fix the typo in the README

The agent then works on your own files, next to any changes you haven’t committed. Give it one job at a time there.

What works today

  • @shop! and @~/code/shop!, and any folder outside git.

Hand over a long log or spec

Paste it straight into the task box. Anything over 8 KiB shows as a chip, such as [paste 32.8 KB · 700 lines], and reaches the agent whole:

@shop explain why this test fails: [paste 32.8 KB · 700 lines]

Or keep it in a file and pass it to irie ctl spawn with -. A task over 100 KiB goes to the agent as a file it’s told to read in full.

What works today

  • Tasks and pastes of any size, sent word for word.

Keep agents working while you’re away

Your agents live in tmux, not in the window, so they keep working after you close it. Open it again later with irie.

Irie can also run on another computer, such as a Linux server, and you can check in over SSH, a safe way to use another computer’s terminal:

ssh alice@example.com
irie

Several windows can show the same Irie at once, from one computer or many.

What works today

  • Closing the window, opening it again, and opening it from more than one place.

What is planned

  • Opening Irie from the Mac’s Spotlight, in a Ghostty window of its own. Planned
  • A desktop alert when an agent needs you. Planned

Let an agent hand work to another

The agents Irie starts can run irie ctl spawn themselves. So an agent can hand a small part of its work to a helper on another profile, each in its own row.

Split this refactor into parts. Start a helper for each small part with
"$IRIE_BIN" ctl spawn --wait @shop +local "<the part>"
and read their branches before you merge them.

IRIE_BIN holds the path to irie, which Irie gives every agent it starts.

What works today

  • Agents starting helpers with irie ctl spawn, and checking on them with irie ctl list.

What is planned

  • The helper’s result coming back to the first agent as a note. Planned

The privacy plugin

Irie’s plugins are sets of features that go on and off together. The first, Privacy, holds the next three recipes: a dead man’s switch for your family, Mullvad VPN in Irie, and Mullvad Browser for agents.

  1. See how each part stands on your computer, and what each still needs: 
    irie plugins
    Or type :plugins in a task bar, or open the Mac app’s Settings › Plugins.
  2. Set up each part in turn. It asks before it installs or changes anything: 
    irie setup privacy
    Or type :setup privacy in a task bar.
  3. To turn the whole plugin off, whatever each part’s own switch says: 
    irie plugins off privacy

Set up a dead man’s switch

If something happens to you, the people you love need to know what to do, and how to get into the accounts that matter. Irie walks you through setting that up, one step at a time. If you stop checking in, you get a reminder first; much later, the people you chose get an email that says what has happened and what to do.

  1. Type :setup switch in the task bar, or in the Mac app choose Plugins › Dead man’s switch › Set Up….
  2. The first time, Claude Code asks whether to trust the guide’s folder. It’s Irie’s own: choose Yes, I trust this folder.
  3. Answer the guide’s questions: who should be told, which password manager you use, which phone you have, and how often you want to check in. It suggests every 14 days: a reminder 2 days after a missed check-in, and the email to your people 16 days after that.
  4. Write the letter with it: READ ME FIRST, which says where things are and what to do first. You keep it in your password manager. It never holds a password.
  5. Give your people emergency access in your password manager. The guide tells you where to click; the clicks are yours.
  6. Make a free account at Healthchecks.io and a key for it. Copy the key, then type this, and Irie keeps it where only you can read it: 
    ! "$IRIE_BIN" dms key --paste
  7. The guide makes two checks: a reminder for you, and an alarm for your people. You add their email addresses in Healthchecks, and tick who hears what.
  8. Pick how to check in: an “I’m OK” shortcut on an iPhone, or an “I’m OK” contact on any phone, or both. A calendar file reminds you every other Sunday, and once a year to look it all over.

What you tell the guide goes to your agent’s AI company, like any conversation. It never asks for a password, and you can stop after any step and come back.

What works today

  • The guide, with steps for Bitwarden, 1Password, Proton Pass, KeePassXC, Apple Passwords, Google Password Manager, LastPass and Dashlane, and for Google’s and Apple’s own backups.
  • irie dms: the checks, their state, a check-in from your computer, pausing them, the phone’s shortcut and contact, and the calendar file.

Mullvad VPN in Irie

If you use Mullvad VPN, Irie can show it where you already look, and change it from any task bar, your phone’s included.

  1. Turn it on in the Mac app’s Settings › Plugins, or with irie plugins on privacy vpn, or in config.toml: 
    [vpn]
on = true
  2. Type :vpn to see it, :vpn on or :vpn off to connect or disconnect, :vpn se got to go through Gothenburg, :vpn lockdown on to block the network while it is off, and :vpn time for your account’s time left.
  3. Watch its mark: green while connected, yellow while it connects, red when something is wrong. In the Mac app it is a shield in the title bar, and Plugins › Mullvad VPN changes it.

Irie reads your VPN through Mullvad’s own mullvad command. It never reads your account number, and never keeps your own address. Agents can’t change the VPN through Irie: it’s yours.

What works today

  • The words in every task bar; the mark in the sidebar, the Mac app and the phone app’s machine cards, with Connect and Disconnect.

Let an agent browse in Mullvad Browser

Some pages read as almost nothing to an agent’s web fetch: pricing pages and apps that build themselves with JavaScript, and pages behind a click or a form. Irie can hand each Claude Code session a real browser for them, Mullvad Browser. It starts without a window when the agent first needs a page, on a fresh profile that is thrown away when the browser closes. One thing first: a browser under remote control tells websites so, so it no longer looks like every other Mullvad Browser, and it keeps no logins. If what you want is your agents’ traffic away from your own address, Mullvad VPN does that for every browser.

  1. Set it up. This installs Mullvad Browser if you don’t have it (with Homebrew on a Mac, once you say yes), opens a page the way an agent would, and turns the browser on for new sessions: 
    irie setup browser
  2. Start a task. Its agent can open and search, read on through long pages, click, type and take screenshots; each step shows in the conversation.
  3. To have the browser leave from another address than the rest of your computer, give it one of Mullvad’s SOCKS5 proxies, from a relay other than your VPN’s, in config.toml: 
    [browser]
proxy = "socks5://nl-ams-wg-socks5-001.relays.mullvad.net:1080"

The browser listens on your own computer only, closes after 10 minutes without a call, and ends with its session. [browser] connector = "off" turns it off again.

What works today

  • Claude Code sessions with Mullvad Browser 16 on a Mac. Another Firefox works too, with [browser] path. Other agents and the Mac app’s Settings don’t have it yet.

The charters, as a map

The Charters plugin keeps thirty-eight texts of rights word for word, from Magna Carta to the Disabilities Convention, the Declaration of Independence, the Constitution and the Bill of Rights among them, each checked against other copies. Its map, the Charters Graph, lays them on a timeline by when and where they were made, with how each drew on the ones before it and the rights each one names. Explore the map here, in your browser: it is one of this site's two pages with a script, and it loads nothing from elsewhere.

  1. Turn the plugin on in the Mac app’s Settings › Plugins, or with: 
    irie plugins on founding
  2. Open Window › Charters Graph, or the map button beside the Charters tab’s choice of text, which opens it at that text.
  3. Pick a text, an amendment or a right, such as Trial by jury. The map lights what it bears on, and the card beside it gives the words, with the passages each link quotes lit.

What works today

  • The map in the Mac app and on this site: 1,577 articles, sections and chapters, 42 rights and ideas, and 76 links between the texts, most quoting both and each pinned to the passages it quotes; search in any spelling, so “chuse” finds “choose”.
  • irie ctl charters graph, which says where the page is on your computer, to open in a browser.

Your markets, as a map

The Markets plugin shows a market map of your own in a window beside your sessions: a page you keep in a folder, often beside the research and the scripts that build it, loaded again each time it is rebuilt and kept from the network. Irie People keeps one in the open: the markets the largest US companies hold and the boards behind them, with which boardrooms touch which markets and who sits on two boards in one. Explore it here, in your browser.

  1. Turn the plugin on in the Mac app’s Settings › Plugins, or with: 
    irie plugins on markets
  2. Open Window › Markets (⇧⌘M) and choose the folder that holds your map’s index.html, or set markets.folder in config.toml. To show Irie People’s map there, clone it and choose its folder: 
    git clone https://github.com/irie-people/markets
  3. Type :markets and a task, such as “map the US airline market”, to start a session that works in that folder; in an empty one it makes a map. The window shows each rebuild once it is written.

What works today

  • Irie People’s map on the web: 80 markets in 12 verticals, every share dated and sourced, and the boards of 587 of the largest US companies, with 5,461 directors and their public roles and political donations, from LittleSis, Wikidata and the SEC’s filings.
  • The Markets window in the Mac app, which loads nothing from the network, and :markets, which shows it or starts a session in its folder.

Common Schools, as pies

The Charters plugin's second part draws America's public schools as pies that open into smaller ones: how they began, the 48 states of 1922 by the land Congress gave them for their schools, with the laws that founded them kept word for word as the charters are; what the school buildings need a year and who pays; who makes and owns the buses; and the Supreme Court's decisions on religion in schools. Every figure names its source. Explore it here, in your browser: like the charters' map it loads nothing from elsewhere.

  1. Turn the plugin on in the Mac app’s Settings › Plugins, or with: 
    irie plugins on founding
  2. Open Window › Common Schools, or Open Common Schools in the Plugins menu.
  3. Pick a slice, or its row in the table beside the pie. A slice with parts opens into a pie of its own; one without says what it is, with the texts behind it. Escape goes back up a step.

What works today

  • Four pies to start from, each slice’s amount and share in a table beside it, and 25 texts word for word, from Massachusetts Bay’s school laws of 1642 and 1647 to the Ten Commandments laws of 2024 to 2026, each with its links to the texts it drew on.
  • irie ctl schools, which says where the page is on your computer, to open in a browser.
